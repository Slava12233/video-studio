# The marketing harness vault is the house style

**The fact.** Two of Slava's harnesses on this laptop already run an Obsidian-vault memory: `marketing-team-harness-main` (whole folder registered as a vault; `memory/` with a README contract, `HOT.md` ≤ 60 lines generated by `build-hot.mjs`, `INDEX.md` one line per note, `lint.mjs` with a secrets and PII scanner, `.base` dashboards with Hebrew labels, a Hebrew HOME and inbox, SessionStart/SubagentStart/PreCompact hooks, `/sync` and `/consolidate`, the kepano Obsidian skills vendored) and `RealEstateTeam` (`memory/HOT.md` generated, `INDEX.md` grepped never read whole, `_TEMPLATE.md` entries, `agents/<name>.md` per actor, "bounded read-first, write-last"). Obsidian itself was installed machine-wide and the CLI already enabled in its config before this studio touched it.

**Evidence.** The files named above, read 2026-11-09; `%APPDATA%\obsidian\obsidian.json` listed five registered vaults and `"cli": true`.

**How to apply.** When a harness-level feature is needed here (memory, hooks, lint, dashboards), look at the marketing harness first and adapt: same contract vocabulary (`type`, `created`, `updated`, `status`, `maintained_by`, `categories`, `summary`, `as_of`, `source`, `supersedes`), same caps (HOT 60 lines / 8 KB, HOME 150, note 300), same rituals. Differences chosen for the studio: tools live in `tools/memory/` (this repo's convention), projects replace campaigns, lessons replace learnings and have `promoted_to` into `docs/`, no commit at `/sync` (Slava commits), other vaults' `open` flags are never touched by `obsidian-setup.mjs`.
