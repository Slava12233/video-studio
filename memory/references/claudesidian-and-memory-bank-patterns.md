# claudesidian and the agent-memory patterns

**What it is.** `claudesidian` (2,606 stars, MIT, last push 2026-04-11): a personal Obsidian vault starter for Claude Code with PARA folders (`00_Inbox` … `06_Metadata`) and commands (`/init-bootstrap`, `/thinking-partner`, `/daily-review`), installed by `install.sh` with zsh/bash steps, no hooks, Windows unmentioned. Cline's Memory Bank: `projectbrief.md`, `productContext.md`, `systemPatterns.md`, `techContext.md`, `activeContext.md` (current state, overwritten, not a log), `progress.md`, all read at every task start (does not scale past one project). CoALA (arXiv 2309.02427): working, episodic, semantic and procedural memory. Letta/MemGPT: editable in-context core blocks vs searchable archival memory, and sleep-time agents that consolidate in the background. Methodologies for Obsidian: PARA, Zettelkasten / evergreen notes (one claim per note, titled as the claim), LYT maps of content, Johnny.Decimal (numbers only on top folders).

**Why it matters here.** They name the layers this vault already has and the pitfalls: archiving a project must not archive its lessons; an index read whole does not scale; a hot file needs a hard budget.

**What we took, or why not.** Borrowed: `state/current.md` as the Cline `activeContext` (true now, overwritten) with `sessions/` as the episodic log and `lessons/` + `docs/` as semantic memory, skills and rules as procedural memory; maps as maps of content; one fact per lesson note titled as the claim; `/consolidate` as the sleep-time pass; projects archived while lessons stay. Not installed: `claudesidian` (personal vault, bash installer, no Windows).
